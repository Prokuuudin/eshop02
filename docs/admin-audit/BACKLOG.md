# Hairshop Pro: backlog после задачи «аудит админских действий»

Создан: 2026-11-11 (Europe/Riga), при закрытии задачи (см. [HANDOFF.md](HANDOFF.md)). Production = `c0162740`; продовая линия — `release/2026-11-08-prefetch-catalog` (`8a16c48a`). Исправлено после создания: Vercel Preview (`.next/lock`) — PR #31.
Каждый пункт — отдельная задача со своим решением владельца; в закрытую задачу они не входят.

## 1. Надёжность аудита, который пишется после действия

Действие выполняется, а запись `AuditLog` делается после него или в отдельной транзакции: при сбое записи действие остаётся без следа.

- `POST /api/admin/grins-import/apply` — импорт применяется до отдельной audit-транзакции.
- `POST /api/admin/grins-import/preview`.
- `POST /api/admin/import`.
- Отправки: `POST /api/admin/notifications/send`, `orders/send-invoice`, `returns/notify`.
- `POST /api/admin/storefront-cache/revalidate`.
- Рассылки: кампания правил карты может повторить до 50 писем, если процесс убит посреди пакета; у `broadcast` нет `maxDuration`.
- Отклонённый вход сотрудника пишется через `after()` после ответа (намеренно — защита от определения аккаунтов по времени ответа); сбой этой записи только логируется.

## 2. E2E: ремонт набора, изолированная БД, CI

- Полный набор (348 тестов) красный и на `a4cecbb3`, и на `c0162740`: в dev-режиме на реальном каталоге (18,5 тыс. товаров) — таймауты 30 с и прерванные переходы; устаревшие локаторы.
- Устаревшие тесты: «cart drawer opens and closes on outside click» (панель теперь закрывается анимацией `animate-out`, тест ждёт `translate-x-full`); «checkout submit redirects to order details page» (по умолчанию самовывоз — полей адреса нет, нужен выбор магазина `#pickup-store`; кнопка отправки вне формы, `form="checkout-form"`).
- `guest-price-leak` ложно срабатывает на реальном каталоге: «7.74» — номер оттенка («Krāsu numurs»), не цена. Нужен фиксированный каталог.
- Клиентский UI считает вход только по данным формы входа (localStorage); вход одним API-запросом UI не видит — тесты UI-сценариев должны входить через форму или ставить `eshop_current_user`.
- Для заказов в чистой БД нужна `KeyValueSetting grins-prices-only-maintenance = {"checkoutClosed": false}` (иначе 503 `checkout_maintenance`, fail closed по замыслу) — добавить в `e2e/global-setup.ts`.
- Production-сервер по http на localhost непригоден (`upgrade-insecure-requests`, HSTS, Secure-cookie): нужен локальный HTTPS (рабочий образец: `next()` + `https.createServer` с эмуляцией `x-iisnode-remote_addr`) или запуск за TLS-прокси.
- Изолированная тестовая БД (Docker PostgreSQL или одноразовая Neon-ветка, не production и не общий staging) и секрет `E2E_DATABASE_URL` в CI. Сейчас браузерные job в CI зелёные, но шаги `playwright test` пропускаются: доказана только установка браузеров.
- Тесты, временно написанные для приёмки PR #30 (гость без цен в API; вход через форму → корзина → заказ банковским переводом с проверкой заказа в БД), стоит оформить постоянными.

## 3. Миграции на пустой БД

`prisma migrate deploy` на пустую PostgreSQL падает на `20260824190000_add_contact_message_answered` (`relation "ContactMessage" does not exist`): история миграций не воспроизводится с нуля, `prisma migrate dev` (shadow DB) не работает по той же причине. Тестовые стенды сейчас создаются через `prisma db push`. Нужен baseline-снимок схемы (squash) без изменения production-БД; production-миграции не трогать.
