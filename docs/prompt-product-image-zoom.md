# Контекст проекта (важно, читай перед кодом)

- Целевой файл: `components/ProductGallery.tsx`. Главное изображение — `next/image` с `fill`, `object-contain`, внутри `<div className="product-detail__image">` → `<div className="relative mx-auto w-full sm:w-1/2 aspect-square ...">`. Контейнер квадратный (`aspect-square`), но `object-contain` — картинка может не заполнять весь квадрат (letterbox сверху/снизу или по бокам в зависимости от пропорций исходника).
- Родитель `ProductPageContent.tsx` уже помечен `'use client'` — новому компоненту зума **не нужна своя директива** `'use client'`, он наследует client-boundary.
- `images: string[]` — обычные URL (мигрированы из nopCommerce/hairshop.lv через Neon). **Мультиразрешение (2x/3x) для товаров сейчас не гарантировано** — большинство изображений одноразмерные. Значит: hi-res-режим должен быть опциональным пропом с graceful fallback на обычный `src`, а не обязательным требованием. Не блокируй фичу на отсутствии hi-res-версий.
- Есть переключение миниатюр (`activeImage` state, `product-detail__thumb` кнопки) — зум должен корректно пересоздаваться/сбрасываться при смене `activeImage`, не залипать на старой картинке.
- Дизайн-система проекта — смешанная: Tailwind-утилиты + отдельные BEM-классы как структурные хуки (`product-detail__image`, `product-detail__thumb`). Новые элементы зума называй в этом же стиле, например `product-detail__zoom-lens`, `product-detail__zoom-pane` — не вводи новую конвенцию именования.
- Комментарии в коде — по-русски, только там, где неочевидна причина (как существующий комментарий про `isEmbedUrl`), не пересказывай что делает код.
- Мобильный трафик существенный (LV-рынок, B2B и B2C) — touch-поведение обязательно, не просто "отключить на тач".
- Схему БД/данные не трогать — задача чисто фронтенд.

# Что реализовать

При наведении курсора на главное изображение товара:

- обычный курсор скрывается над зоной картинки;
- появляется полупрозрачная квадратная линза, плавно следующая за курсором;
- линза **никогда не выходит за границы фактически отрисованного изображения** внутри `aspect-square` контейнера — учитывай, что при `object-contain` реальная картинка может быть уже/ниже контейнера (letterboxing), линза должна ограничиваться реальным bounding box изображения, а не контейнера;
- одновременно показывается увеличенный фрагмент.

Увеличенный фрагмент — в отдельной панели справа от изображения на десктопе (предпочтительный режим), с архитектурной возможностью переключить на режим "внутри изображения" без переписывания логики линзы. На мобильных/узких экранах, где панели справа нет места (텍스트: `sm:w-1/2` контейнер уже занимает половину ширины только от `sm` breakpoint) — панель нужно либо скрывать под отдельный touch-UX (см. ниже), либо адаптивно переключать в режим "внутри изображения".

# UX и производительность

- `requestAnimationFrame` вместо прямого обработчика на каждый `mousemove`;
- движение линзы и панели — через `transform: translate3d(...)`, не `top/left`;
- `will-change` точечно, только на элементах в момент активного зума, снимать после;
- анимация появления/исчезновения — плавная (opacity + небольшой scale), без рывков и мерцания;
- ноль лишних DOM-узлов на карточках, где зум ещё не активирован.

# Retina / hi-res

Проп для опционального hi-res-источника (например `hiResSrc?: string`), используется в панели увеличения если передан, иначе — увеличение через CSS-transform того же `src`, что и в превью. Не завязывай архитектуру на обязательное наличие второго файла.

# Lazy init

Не инициализировать зум-логику (слушатели, вычисления bounding box) для изображения, пока пользователь не навёл на него курсор впервые (`onPointerEnter` создаёт контроллер, `onPointerLeave`/unmount — уничтожает). На странице товара картинка одна активная за раз (не грид из десятков карточек), поэтому IntersectionObserver здесь избыточен — это оправдано на листинге товаров, но не на странице одного товара. Объясни в ответе, почему для `ProductGallery` выбран именно этот вариант, а не IntersectionObserver.

# Touch

Отдельный UX, не имитация hover: например long-press открывает увеличенный фрагмент на весь экран (или модалку), либо тап переключает в режим "pinch-to-zoom" через нативные возможности браузера. Обоснуй выбор.

# Accessibility

- `prefers-reduced-motion` — отключить/упростить анимации;
- клавиатурная доступность — фокус на изображении не должен ломать существующую табуляцию по миниатюрам;
- ARIA — зум декоративен по отношению к контенту (сам `alt` уже на `<Image>`), не дублировать семантику, но не мешать screen reader'ам.

# API компонента

Предложи чистый TypeScript API (пропсы React-компонента, не императивный класс — проект целиком на React/hooks, ProductGallery уже функциональный компонент с `useState`). Обоснуй форму API (компонент/хук `useImageZoom` + презентационные части) в контексте того, что это будет вызвано прямо внутри `ProductGallery.tsx`, а не как отдельная библиотека на страницу.

# Масштаб

Проп `zoomFactor` (2x/3x/4x) без изменения остальной архитектуры.
