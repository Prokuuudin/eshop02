# Как вручную обновить цены и остатки Hairshop Pro из GrinS

Ручное обновление — резервный способ. Оно работает без FTPS и без автоматической синхронизации и делает то же самое, что автоматическая синхронизация: меняет только **цену (price2)** и **остаток** товаров, которые уже связаны с GrinS. Новые товары не создаются, товары не скрываются, названия, описания и фото не меняются.

## 1. Где взять файл

Нужен файл `export.xml`, выгруженный из GrinS (Hairshop Pro exporter, см. `docs/grins-pro-exporter-runbook.md`).

- Файл формируется на компьютере с GrinS. **Автоматической доставки файла к вам нет** — его нужно скопировать с этого компьютера (или из папки, куда exporter его сохраняет).
- Не открывайте и не пересохраняйте файл в Excel или блокноте — загружайте как есть.
- В самом файле нет даты выгрузки. Перед загрузкой убедитесь, что файл свежий (дата изменения файла — сегодня, после последних изменений в GrinS).

## 2. Куда загрузить

Админ-панель → **Каталог → Импорт** (`/admin/import`) → блок **«Обновление цен и остатков из GrinS (вручную)»**.

Доступно только администратору (нужны права `catalog.update` и `prices.update`) после входа в админ-панель.

## 3. Проверка (предварительный просмотр)

1. Нажмите «Выбор файла», выберите `export.xml`.
2. Нажмите **«Проверить файл»** (5–15 секунд). Каталог на этом шаге **не меняется**.
3. Посмотрите сводку:
   - **Записей в файле** — обычно около 16 000;
   - **Сопоставлено** — сколько товаров будет обновлено;
   - **Не сопоставлено** — товары GrinS, которых нет в магазине; они пропускаются (не создаются);
   - **Изменится цен / остатков**, **Остаток станет 0**;
   - **Цена price2 = 0** — для таких товаров цена в магазине сохранится, но товар помечается «нет цены ERP»;
   - **Дубликаты SKU, конфликты, некорректные значения** — должны быть 0;
   - **Деактиваций** — всегда 0.
4. Красный блок **«Критические ошибки»** — применить нельзя, кнопки нет, каталог не изменён.
5. Жёлтый блок **«Предупреждения»** — прочитайте. Применять можно, только если понятно, откуда они.

## 4. Когда НЕЛЬЗЯ подтверждать

- Есть красный блок (система сама не даст применить).
- Файл старый или вы не уверены, откуда он.
- «Записей в файле» заметно меньше обычного, «Остаток станет 0» или «Изменится цен» — сотни/тысячи без понятной причины.
- В предупреждениях «more than 50%» по ценам, а массового изменения цен в GrinS не было — откройте «Примеры записей» и сверьте 2–3 товара с GrinS.
- Идёт автоматическая синхронизация (жёлтая надпись) — подождите 5–10 минут.

## 5. Применение

1. Поставьте галочку «Я проверил сводку…».
2. Нажмите **«Применить обновление»** и не закрывайте страницу (обычно 10–60 секунд).
3. Проверка действительна 30 минут. Если истекла — загрузите файл заново.

Перед применением система ещё раз повторяет все проверки на текущих данных и сохраняет резервную копию цен и остатков.

Изменённые товары получают новую revision: ранее открытая форма администратора при сохранении получит конфликт 409. Перезагрузите карточку и повторите нужные правки с актуальной ERP-ценой. Повторный импорт без изменения полей не меняет revision.

## 6. Как понять, что обновление завершилось

- Зелёное сообщение **«Обновление завершено»** с номером запуска.
- В «Журнале синхронизаций» внизу блока — строка «вручную», статус `completed`, ваше имя файла и e-mail.
- Проверьте 2–3 товара на сайте/в карточке товара.

## 7. Что делать при ошибке

| Сообщение | Что делать |
|---|---|
| Критические ошибки / повторная проверка не пройдена | Каталог не изменён. Возьмите свежий файл из GrinS. Если повторяется — сообщите администратору. |
| Идёт другая синхронизация | Подождите 5–10 минут и загрузите файл заново. |
| Проверка устарела / не найдена / заменена | Загрузите файл заново. |
| Связь прервалась | **Не повторяйте сразу.** Через 1–2 минуты нажмите «Обновить» в журнале: если там `completed` — всё готово. |
| Ошибка при применении (`failed`) | Каталог мог обновиться **частично**. Прекратите работу с ценами и сообщите администратору — см. раздел 8. |

## 8. Для администратора: восстановление

При HTTP timeout или потере связи сервер может продолжать импорт; разрыв связи не означает отмену. Не нажимайте Apply повторно и не перезапускайте приложение до проверки журнала. Один preview применяется только один раз.

Если после перезапуска статус остался `running`, а `productsSynced` не растёт более 5 минут, запуск подозревается прерванным (это не доказательство завершения). Блокировка действует 30 минут **после последнего heartbeat**, а не после начала. Дождитесь истечения lease и проверьте отсутствие активного процесса; затем повторно загрузите правильный файл. Следующий запуск пометит старую запись failed после истечения срока. Во время импорта запрещены deploy, recycle и restart приложения.

`failed` означает, что часть пакетов по 200 товаров записана, часть нет. Каждый товар при этом имеет либо старое, либо новое значение (ничего не «портится» наполовину).

- **Файл был правильный, сбой технический** (сеть, БД): загрузите тот же файл ещё раз — повторный импорт безопасен и дозапишет остальное.
- **Файл был ошибочный** (неверные цены/остатки): предпочтительно импортировать правильный свежий XML. Восстановление копии допустимо только сразу после инцидента, при остановленных продажах, резервированиях/отменах заказов и изменениях каталога. Оно возвращает старый stock и может вернуть уже проданные единицы, создав риск перепродажи. Нужны разрешение владельца, dry-run и сверка заказов после снимка. Ключ копии — в журнале (`backupKey`) и в ответе применения. Хранятся 5 последних копий: сохраните ключ первой доинцидентной копии и не запускайте бесконечные повторы, которые вытеснят её.

```bash
npx tsx scripts/restore-grins-manual-import.ts --list
npx tsx scripts/restore-grins-manual-import.ts --backup "<backupKey>"            # проверка: сколько товаров отличается
npx tsx scripts/restore-grins-manual-import.ts --backup "<backupKey>" --execute  # восстановление
```

Восстановление возвращает цену, остаток, флаги «нет цены ERP» и ручное подтверждение цены для связанных товаров — одной транзакцией, под той же блокировкой, что и синхронизация, с записью в журнал (тип `restore`). Оно **перезапишет** изменения этих полей, сделанные после импорта (dry-run показывает количество). Справочные данные ERP (price1–4, остатки по складам) не восстанавливаются — их обновит следующий правильный импорт. Дополнительная страховка — восстановление Neon на момент времени (`backup-retention-plan.md`).

Скрипт работает с той базой, что указана в `.env.local` / `DATABASE_URL` — запускайте осознанно.

Снимок читается одним SQL statement, но общий sync lock захватывается только внутри runSync, после снимка. До независимой проверки этой границы не запускайте ручной импорт одновременно с cron/другим импортом или изменениями каталога. Если другой sync выиграл гонку, импорт будет skipped; копия такого запуска не является подтверждённой точкой восстановления перед успешным импортом. Dry-run восстановления также не фиксирует состояние: продажи должны оставаться остановленными до завершения execute и сверки.
